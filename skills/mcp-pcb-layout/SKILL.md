# AI + MCP 辅助画 PCB

版本：2026-10-20，经过 QPA2609 三轮实跑（两轮远程 + 一轮本机）。用户要求只在明确说"用这个 skill"时加载。

## 一句话

**设计由规划端一次想清楚、算出每一个坐标、自己验证；执行端只照清单施工、逐项读回核对、不符就停。** 执行端看不见设计意图，能依赖的只有数字和清单；规划端看不见 AD，能依赖的只有读回的数据、DRC 报告文件和用户的眼睛。

## 两种工作方式

| | 本机模式（现在主要用） | 远程模式 |
|---|---|---|
| 什么时候 | AD + eda-agent 就在这台电脑上（`E:\Altium_designer\`） | AD 在另一台电脑上，用户传文件和截图 |
| 规划端 | 主会话：建模、算坐标、自检、写任务说明、改 PcbDoc 文件、核对 | 主会话：同左，但只能出数据包 |
| 执行端 | `eda-agent-operator` 子代理：只读 / 导出用 **Haiku**，修改 / DRC 用 **Sonnet**（规矩见 `eda-agent` skill） | 那台电脑上的代理（可以是便宜模型），照 `ops.jsonl` + RUNBOOK 做 |
| 交接物 | 任务说明（`references/subagent-prompts.md`）+ 期望清单 CSV | 一个 zip 数据包（`references/data-package.md`） |
| 核对 | 主会话自己读 DRC 报告、重新解析保存后的 PcbDoc | 报告 + 日志 + 用户截图 |
| 工具做不了的 | 规划端直接改 PcbDoc（`references/pcbdoc-direct-edit.md`） | 写进"你自己要做的"，或写好备选办法 |

## 工作循环

```
侦察（读文件 / 子代理只读导出）→ 建模（现有设计全部的铜 + 库里全部图元）
→ 布局 / 算坐标（元件、线、过孔、缝合孔、原理图、丝印）→ 自检 + 出图 → 动手前自查清单
→ 执行（子代理按任务说明 / 远程代理按数据包）→ 逐项读回 → DRC 报告
→ 主会话核对 → 问题分四类 → 复现 → 改数据源 → 只针对差异再做一轮
```

## 17 条经验（完整版和例子在 `references/lessons.md`）

一、交给谁决定
1. 不把设计决定交给工具的"自动"功能，坐标自己算（自动打缝合孔 → 孔又稀又不错行）。
2. 写成"可选"的，执行端一定不做；人会看的东西（丝印、密度）都写成正式步骤并给数字。
3. 规则打架时写明优先级：禁止条款 > 阶段指令 > 建议。

二、删除
4. 只按"允许删除清单"或"白名单差集 + 数量正好 N"删；删完数必须保留的对象。
5. 不认识的东西只查不删。

三、现有设计和库
6. 先侦察再规划；现有设计的**所有**铜都进模型。
7. 库要按"层 × 图元类型"全列一遍（禁布区、封装自带的 Top Overlay 文字），列出来还要用上。

四、验证
8. 工具说"成功"不算；读回原始数据或 AD 的 DRC 报告文件才算；执行端的"解释"也要核对。
9. DRC = 0 不等于做对了：和原设计比"像不像"，看图 / 截图。
10. 差量修改基于"实际做成的样子"，设计和实际两个模型都检查。

五、执行端
11. 给便宜模型的清单要"不用想"：一行一个操作，参数写死，核对能量化，失败处理只有几种。
12. 反馈分四类：我的数据错 / 执行端错 / 工具限制 / 说明书缺漏；我的错先在自检里复现。
13. 没验证过的工具能力先拿一个对象试，并写好"做不到时怎么办"。
14. 远程包必须自带全部文件，一次只出一个。

六、本机模式
15. 工具做不了的，规划端直接改 PcbDoc；但离线核对全对不等于 AD 认（层号存了两份），**必须让 AD 重新打开逐项读回**。
16. 估算会偏，DRC 是最后的裁判；按 DRC 迭代，改内容（删字、缩字）问用户。
17. 删除这类不可逆操作由用户决定；权限检查拦下时不改权限、不绕过，请用户在 AD 里手动做。

## 硬规矩

- 主模型不直接调用 eda-agent；派子代理时先告诉用户用的哪个模型（`eda-agent` skill）。
- 子代理默认只读；可以改时说明里写清"只准改什么"，并写"任何一项不符就停，不保存"。
- 改之前有备份：`<AD 工程根>\备份\<工程>_<时间>_<说明>\`，一次一个文件夹，保持原目录结构。
- 直接改 PcbDoc 必须先让 AD 关掉工程；只改固定长度字段；改完 `pcbdoc_io.py v7check` = 0，再让 AD 读回。
- DRC 以报告文件为准（`Project Outputs for <工程>\Design Rule Check - <PCB>.drc`），主会话自己读。
- 设计决定（删内容、改方案、放宽规则、放宽权限）交给用户。

## 脚本（`scripts/`，都用 `python -I` 跑，路径作参数）

| 脚本 | 做什么 |
|---|---|
| `pcbdoc_io.py` | 读 / 改 PcbDoc：文字（两份层号一起改）、线、弧、过孔、板区域、元件序号；`summary` / `texts` / `v7check` / `v7fix` |
| `pcblib_inventory.py` | 每个封装按"层 × 图元类型"计数，标出要查的 region 和 Top Overlay 文字（`--texts` 列出文字内容） |
| `drc_report.py` | 汇总 .drc：每条规则违规数、涉及指定文字的违规（`--texts`）、按对象类型分组（`--kinds`） |
| `silk_geom.py` | 丝印文字外框模型 + 真实板子的障碍物 + 合格判定 + 就近搜索 |

需要 `olefile`、`shapely`（`silk_geom`）、`matplotlib`（出图）。
