## 本文件夹里有什么、按什么顺序读

做一块新的射频链路板（或在已有板上加电路）时，建议按这个顺序看：

1. **`design_basis/`：设计依据。** 每个数字的来源。
   - `射频测试板统一设计标准_草案.md`：叠层、50 Ω 线宽、屏蔽孔、连接器、阻焊、AD 规则、模块切口，全组照做的标准；
   - `厚度阻抗线宽统一说明.md`：讲道理的版本；
   - `板子厚度说明.md`、`叠层与射频线.svg`；
   - `偏置供电_方案一完善说明.md`：VD / VG 供电电路，每个电阻怎么算、上电顺序、调试步骤。
2. **`../../references/rf-board-calcs.md`：计算方法。** 把上面的依据整理成"定什么 → 怎么算 → QPA2609 的值 → 怎么核对"。
3. **`data/`：交给执行端的全部数据表**（原样）。`data/README.md` 逐表讲每一列的意思、怎么算出来、执行端怎么用、按什么标准核对。
4. **`manuals/`：说明书原文**（AGENT_GUIDE、RUNBOOK、第二次修改手册、人类版指南）。`manuals/README.md` 讲每一节为什么要有、写的时候注意什么。
5. **`subagent_dispatches/README.md`：本机模式下派子代理的 12 次真实往返**，包括任务原文、汇报原文、主会话怎么核对和接着处理。
6. **`round3/`：第三轮的脚本和结果。**

## 任务

在已经做完布线、DRC 全 0 的 QPA2609 射频测试板（25.4 × 51.4 mm，4 层）上，加一整套 12 V 供电：LTC3260 + LT3094 + LT3045，47 个元件。

要求做成一个模块：
- 板子拉长到 108.5 mm；
- 供电元件全部放在两条切口线 x = 6.0 / 19.4 之间；
- VG 走 GND3 层，从芯片和屏蔽孔之间的缝里穿过去，一个屏蔽孔都不拆。

**修法**：

2. 主会话改 PcbDoc：10 个位号回到 Top Overlay（精确坐标 + 旋转）、12 个字精确坐标、13 个封装文字挪 Mech13、板区域上边改到 6007 mil；

## 规划端工具链的小坑（本机）

- Git Bash 的 heredoc 里写中文和反斜杠容易出错 → 脚本先用 Write 写成文件再运行。
- Windows 路径写进 Python 普通字符串：`\2026...` 里的 `\20` 会被当成八进制转义，变成一个控制字符 → 用原始字符串 `r'...'`，或者脚本先写成文件再跑。
- 用 Python 生成 Python 或 f-string 代码时，`'\\n'` 会被转义两次，变成真的换行 → 生成完立刻跑一遍，看是否报语法错误。
- 出图脚本会先清空 `图\` 文件夹 → 要复制进去的图必须在清空**之后**放（写在同一个脚本里）。
- 函数参数不要叫 `name`、`kind` 这类常用名，会和 `**params` 里的同名键冲突。
- 临时文件放 `E:\<项目根>\电路控制\temp\`，不放 C 盘；一轮一个子文件夹（`temp\round3\`）。
- 在 bash 的 heredoc 里写 Python，字符串里的 Windows 路径（`\542`、`\a`）照样会被当成转义 → 带路径的内容用 Edit / Write 工具写，或者 Python 里一律用 `r'...'`。第三轮又踩了两次。
- `python -I` 会把当前目录排除出导入路径：脚本里自己 `sys.path.insert(0, 脚本所在目录)`，不要在 `-c` 里 import 同目录模块。
- 一个脚本里既搜索又画图时，把搜索放进 `main()`，否则画图脚本 import 它就会把一分钟的搜索再跑一遍。
- shapely 画带洞的多边形要单独把洞填白，不然外框画成实心块；matplotlib 的 `ax.text` 要 `clip_on=True`，不然图外的标签把图撑得很长。
