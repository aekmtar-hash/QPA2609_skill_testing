# 说明书：写了什么、为什么这么写

这里是 QPA2609 实跑用过的四份说明书原文。写新说明书时，照下面的"必备章节"逐项对，每一节都写明它挡住了哪种出错。

| 文件 | 给谁 | 用在哪轮 |
|---|---|---|
| `AGENT_GUIDE.md` | 执行端（能理解全文的模型） | 第一轮（全量新做），后来按反馈改过 |
| `RUNBOOK_HAIKU.md` | 便宜模型：不理解全文，只按循环逐条做 `ops.jsonl` | 第一、二轮 |
| `第二次修改手册.md` | 执行端 + 人；差量修改 | 第二轮 |
| `完成步骤总指南.md` | 人（同一套坐标，可以手工照做 / 对照检查） | 全程。文中 `图/…` 的分段布线图没收进来，在工程 `7_完成指南\图\` |

## 一、AGENT_GUIDE 的必备章节（按出现顺序）

| 节 | 内容 | 为什么要有 |
|---|---|---|
| 开头三行 | 读者是谁、任务一句话、"人不在场，宁可停下写清楚，也不要猜着改" | 定基调：执行端最大的风险是"自作主张" |
| 给小模型的分流 | "如果你是小模型，直接去 RUNBOOK 逐条做" | 不让便宜模型去理解全文再规划 |
| 0 完成的标准 | 7 条可检查的结果（元件数、板框、DRC 哪些项为 0、丝印、报告） | 执行端知道"做到什么算完"；做不完也要按阶段保存 |
| 1 硬性规则 | 备份；**不准改射频部分**（逐个列出对象）；不改叠层 / 原点 / 已有规则；ECO 有 Remove 就停；只用 ASCII；不准"顺手修"DRC | 射频部分是已经调好的，动一点就要重新验证；这些规则 > 阶段指令 |
| 2 工程现状 | 文件名、叠层、板框、已有规则、已有网络、**关键坐标**、过孔数、铺铜 | 盘点核对的依据；数量对不上就说明打开的不是那块板 |
| 3 坐标 / 单位 / 层名 | 校准公式（用哪几个元件）、角度约定、封装原点、层名映射（GND3 = MidLayer2）、**每一层的总表** | 第一大出错来源。每层表写清"原有对象不准改 / 本次做什么 / 结束时应满足" |
| 4 数据文件 | 每个文件一句话 | 告诉执行端唯一的坐标来源是这些表 |
| 5 库 | 库文件、封装名、**特殊引脚号**（LT3094 底部焊盘是 13 接 N5V） | 封装名、脚号错了，后面全错 |
| 6 执行阶段 P0～P14 | 每阶段：做什么（具体工具）、**核对门槛**、失败怎么办；续做规则 | 一阶段一保存一日志；门槛不过就停 |
| 7 为什么这样设计 | 切口、VG 走 GND3 的路线、跳线、EN− 改接 | **防止执行端"改进"设计**；也是给人看的设计理由 |
| 8 出问题怎么办 | 现象 → 处理（超时、模态框、`?`、固定偏移、0.0x mm 偏差、整数 mil、unrouted 不可信…） | 把已知的坑提前告诉它 |
| 9 日志和报告 | 日志每阶段一段；报告 6 项 | 第二天人能接着做、能判断 |

**写法要点**
- 数字全部来自数据表，说明书里只引用、不重新抄一遍（抄就会不一致）。
- 每条"不准"都具体到对象：`U1、J1～J8、C3…C18、keep_existing_vias.csv 里的 137 个过孔、Top Solder 上的开窗 Fill`。
- 每个"可能失败"的地方都写 on_fail；工具做不了的事写进"人来做"，不要留成"可选"（可选 = 不会做）。
- 第一次实跑后把发现的坑写回原位（例如 P11 写明"不要用 `pcb_place_stitching_vias`，原因是……"），不另开一节"更新"。

## 二、RUNBOOK（给便宜模型）的必备章节

| 节 | 内容 |
|---|---|
| 1 开始之前 | 读日志找断点；校准；备份 |
| 2 **主循环 8 步** | 读 op → 查 TOOL_MAP → 换算坐标 → 查重 → 调用 → 按 verify 读回 → 不过按 on_fail → 写一行日志。批量最多 30 个，但核对仍逐个 |
| 3 坐标换算 | 带 `_mil` 的加偏移，原理图坐标不加；读回先减 |
| 4 on_fail 的含义 | STOP / LOG_CONTINUE / SKIP_PHASE / REPORT 各做什么 |
| 5 TOOL_MAP | 每种 op → 真实工具名和参数名（P0 时查实并写进日志，缺必需工具当场停） |
| 6 复杂 op 的固定做法 | 删缝合孔（差集 + 正好 333）、焊盘核对不过、ECO、DRC 筛孔、DRC |
| 7 绝对不能做的事 | 和 AGENT_GUIDE 第 1 节一致 |
| 8 日志格式 | 给出样例 |
| 9 顺序一览 | 为什么是这个顺序（先清场再放元件、先过孔走线再铺铜…） |

要点：便宜模型**不做判断**，所以所有判断都事先变成"数字相等 / 不相等"和"on_fail 选哪个"。复杂流程不拆成几十条 op，写成一个 op + 固定做法。

## 三、差量修改手册（第二轮）的写法

1. **这次改什么、为什么**：一张表——问题（用户截图里看到的）/ 原因 / 这次怎么改。原因要讲到根上（"工具的间距参数是全局的"）。
2. **和原来不一样的地方**：明确说原来是什么、为什么改。
3. **不改的**：哪些看起来像问题但这次不动，为什么。
4. 每个修改项一节：数据（坐标表、样式要求）+ 预览图 + **删除的方法**（差集 + 正好 N + 删完数一遍）。
5. 给 AI 的执行说明：偏移、阶段表、新增 op 类型对应的工具、禁止事项。
6. 你自己要做的（工具做不了的）。
7. 报告要写什么。
8. 文件清单（**所有引用的文件都要在同一个包里**——第二轮漏了 RUNBOOK）。

## 四、人类版指南的作用

和代理用同一套坐标，分步骤、带图，可以：
- 第二天对照检查代理做的结果；
- 代理做不了的步骤人照着做；
- 讲清设计理由（"和原方案不一样的地方"），用户能看懂为什么。

## 五、第三轮（本机模式）为什么不用写整本说明书

主会话和子代理在同一台电脑上，每一步派一个短任务（`references/subagent-prompts.md` 的模板），子代理汇报后主会话立刻核对、再派下一步。说明书的作用被拆进了每份任务说明里：**目标、只准改什么、预期会看到什么、不符就停、带回什么**。真实的任务说明和汇报见 `../subagent_dispatches/`。
