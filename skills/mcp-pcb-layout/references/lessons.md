# 经验（每条都有实跑里的真实例子）

第 1～14 条来自前两轮（远程模式），第 15～17 条来自第三轮（本机模式）。`SKILL.md` 里只列标题，这里是完整版。

### 一、关于"交给谁决定"

**1. 不要把设计决定交给工具的"自动"功能，要自己算出坐标。**
自动打缝合孔、自动摆位号、自动布线这类功能，参数的意思往往和你想的不一样，结果又只能在图上看出来。
例：第一次实跑用 `pcb_place_stitching_vias`，"间距 1 mm"本意是只让孔离射频线 1 mm，工具却理解成离**所有**东西 1 mm。结果孔又稀又不错行，有 8 个打进焊盘，6 个离原有屏蔽孔太近；DRC 照样是 0，用户看截图才发现"变稀了"。
改法：规划端按网格把 602 个孔的坐标逐个算好、逐个检查，执行端用普通的"放过孔"照表放，再跑 DRC 筛一遍。

**2. 写成"可选"的东西，执行端一定不做；凡是人会看的，都要写成正式阶段，带具体数字。**
例：第一版说明书里丝印写的是"可选，人工可加"。结果 47 个新位号原样带进来，又大又挤、压焊盘，板子看起来一团乱。
人会看的东西包括：丝印（字高、位置、哪些要藏）、缝合孔密度、铺铜名字、和原设计风格一致。

**3. 说明书里两条规则打架时，执行端会按自己的理解选一条，所以要写清楚谁优先。**
例：总规则说"射频部分一概不准动"，P6 又让改 J3～J6 的孔径。代理选了不改（选对了），但这是运气。
做法：写"禁止条款 > 阶段指令 > 建议"；发包前通读一遍查矛盾（见 `checklists.md` A 节）。

### 二、关于"删除"

**4. 删除是最危险的操作，只能按"允许删除清单"来删，或者按"白名单差集 + 数量正好等于 N"来删。**
例：删 333 个旧缝合孔时用"137 个保留孔的差集，正好 333 个才删"，一次成功。后来修孔距报错时，代理临场决定删哪些，把 **14 个原有屏蔽孔**删了，靠事后数"必须存在的 182 个"才发现，再按原坐标补回。
做法：
- 能预先算好的，就给"允许删除清单"（例如 `stitch_vias.csv`：DRC 有问题时只能删这张表里的孔）；
- 删之前先算差集、核对数量；删完再数一遍必须存在的对象，少一个就停。

**5. 不认识的东西只查不删。**
例：截图里板子中间有一条来历不明的横虚线（旧板顶的位置）。差量包里只让代理列出它在哪层、是什么对象，人看了再决定。

### 三、关于"现有设计"和"库"

**6. 先侦察，再规划：现有设计尽量用真实数据，不要只凭记录建模。**
例：只按记录建模，错了 3 处：
- J3～J6 插针的 1 脚是方焊盘，被当成了圆的，新过孔离焊盘角只剩 0.13 mm；
- 两个原有过孔坐标差 0.13 mm；
- 工程里实际挂的是 `PCB1_no3d.PcbDoc`，不是说明书写的 `PCB1.PcbDoc`。

自检时规则 0.15 mm 按 0.2 mm 查，留的余量救了大部分情况，但盖不住 0.13 mm 的建模误差。
第二轮又漏了一次：缝合孔脚本只把"新画的线 + 射频线"当障碍，原板上的 VG 供电线没进模型，一个孔离它 0.025 mm（差点短路），靠 DRC 筛掉。
做法：
- 第一轮先派执行端只读侦察：所有焊盘（形状、尺寸、旋转、网络）、过孔、线、区域，规则（**含是否启用**），工程实际引用的文档；
- 现有设计的**所有**铜都要进模型，不只是"受保护的"那部分；
- 做不到侦察时，余量要大于预计的建模误差。

**7. 下载的库不能只看焊盘，每个封装要按"层 × 图元类型"列一张表。**
例：D101、FB101、FB102、LED101 的库里藏着 Top 层和禁布层（Keep-Out）上的禁布区，离自己的焊盘只有 0.05 mm，DRC 报了 26 条。之前核库只读了焊盘、外框和本体，全漏了。
第二轮：丝印自检只躲了焊盘和元件外框，没躲封装自带的 Top Overlay 轮廓线，字宽也是按 0.85 × 字高估的，结果新字有 36 条丝印 DRC 违规。
做法：
- 用 `olefile` 统计每个封装每层有哪些图元（track、arc、region、fill、text、body），看到 Top、Keep-Out 层上有 region 就要查；
- 列出来还要**用上**：Top Overlay 上的线和弧要进丝印检查，字宽按 Stroke 字体的真实宽度算。

### 四、关于"验证"

**8. 工具说"成功"不算证据；读回原始数据或 AD 自己的报告才算。**
例：
- `pcb_get_unrouted_nets` 在地铜被删掉时也报 0；
- 规则禁用以后，DRC 仍然按它报了 84 条；
- 工具自己的 `drc_confirmed` 是 false，而 DRC 报告文件里写的是 0；
- DRC 报告里根本没有 Routing Via Style 这一项。

执行端的**解释**也不算证据。第二轮它说"丝印规则已经关回去了，报告里还显示是因为 AD 记住了"；更可能的是规则根本没真关上。

做法：每一步都按对象逐个读回比较；DRC 以 `.drc` 报告文件为准；报告里缺的项自己算；执行端给的原因要找读回数据核对，核对不了就让人在 AD 里看一眼。

**9. DRC = 0 不等于做对了：要和原设计比"看起来像不像"，并且要用户的截图。**
例：第一次 DRC 全 0，但用户一张截图就看出两个问题：孔变稀了、丝印乱。
做法：
- 规划端出预览图；
- 和原设计比数量和密度，例如原 51.4 mm 板范围内原来 333 个缝合孔，新方案 316 个；
- 跑完让用户按 `checklists.md` B 节的截图清单截图。

**10. 差量修改要基于"实际做成的样子"，而且要同时对"设计"和"实际"两个模型都检查。**
例：第一次实跑时，代理为了躲开方焊盘，把一个过孔挪了 0.03 mm；后来我的数据改成挪 0.15 mm 并移动 C118。第二轮的缝合孔如果只按新设计检查，可能会撞上板上实际的那个孔。
做法：
- 把执行端的现场改动写成"实际状态模型"（`pmod_asbuilt1.py`）；
- 第二轮的孔只保留两个模型都通过的位置；
- "必须保留"清单也按实际坐标写（`required_vias_asbuilt.csv`）。

### 五、关于"执行端"

**11. 给便宜模型的东西要做到"不用想"：一行一个操作，参数写死，核对能量化，失败处理只有几种。**
（用户原话："执行的我不可能用opus成本太高更多是类似haiku的角色,只能完全依赖详细说明书和具体参数实现"）
- `ops.jsonl` 的字段：`id / phase / op / params / verify / on_fail`。
  - `on_fail` 只能取 STOP、LOG_CONTINUE、SKIP_PHASE、REPORT 几种；
  - 复杂的固定流程（删旧孔、DRC 筛孔、焊盘核对不过）写成**一个** op，具体步骤写在 RUNBOOK 里。
- 第 0 阶段先把"op 类型 → 真实工具名和参数名"核对一遍写进日志，必需的工具缺了当场停，不要做到一半才发现。
- 坐标约定只有一种：PCB 坐标加偏移，原理图坐标不加；写入和读回都按这个来。
- 能续做：按阶段标记找断点，创建前先查重。

**12. 每一轮都要把反馈拆成四类：我的数据错 / 执行端错 / 工具限制 / 说明书缺漏。**
- 我的数据错：先在自检里**复现**（例如方焊盘按方的建模后，自检报出同样的 0.13 mm），再改数据源，全部重新生成；
- 执行端错：在规则里堵住（比如第 4 条的删除规则）；
- 工具限制：写进 `eda-agent-pitfalls.md`，能交给人的就列进"你自己要做的"；
- 说明书缺漏：补进阶段和清单（比如第 2 条的丝印）。

最后同步更新三处：全量包、差量包、本 skill。

**13. 要用到某个工具能力的步骤，先拿一个对象试；规划端事先写好"做不到时怎么办"。**
例：第二轮丝印要"隐藏位号"和"转文字方向"，这两样都没实测过。结果隐藏工具一调就卡死，AD 重启了两次；工具也转不了文字，执行端临场把 8 个位号换成普通文字。看起来一样，但这些字和元件不再绑定，元件挪了字不会跟着走。这次临场办法还算合理，但不能靠运气。
做法：
- R0 里对一个对象把每种没验证过的能力试一遍（改、读回、改回去），做不到的写进日志；
- 每种没验证过的能力都在说明书里写好备选，例如"隐藏不了 → 挪到 Mech13""转不了 → 不做，列清单留给人手动转"；
- 没验证过的工具放在阶段末尾，调用前先保存（卡死了要重启 AD）。

**14. 发出去的包必须自带全部文件，而且一次只出一个。**
例：第二轮手册写"循环规则见 `8_AI代理包\RUNBOOK_HAIKU.md`"，但用户发过去的 `9_第二次修改.zip` 里没有这个文件；它在 `打包\` 下另一个名字差不多的 zip 里。执行端只好按每条 op 自带的 on_fail 做。
做法：
- 说明书里提到的每个文件都放进同一个压缩包；
- 一次修改只出一个 zip，文件名带轮次和日期，别在两个地方各放一个内容不同的包；
- 发包前解压到空文件夹，按说明书里出现的文件名逐个找一遍。

### 六、第三轮（本机模式）补充

**15. 工具做不了的，规划端可以直接改文件；但"离线核对全对"不等于 AD 认，必须让 AD 重新读回。**
例：第三轮要转 8 个位号的方向、把 13 个封装文字挪层、修板区域，eda-agent 都做不了。规划端用 olefile 直接改了 PcbDoc，离线重新解析 35 条全部正确；AD 重新打开后，属于元件的 21 条却全没生效。原因是文字的层号在记录里存了两份，AD 读的是我没改的那份（@226 的 V7 层号）。子代理按期望清单逐条读回，发现不符就停下、没保存，补改后一次通过。
做法：见 `pcbdoc-direct-edit.md`。先在 AD 里做完能做的并保存 → 关工程 → 按内容找记录、空跑 → 备份 → 改 → 离线核对 → **AD 重新打开逐条读回** → DRC。

**16. 估算会偏，AD 的 DRC 是最后的裁判；按 DRC 结果迭代，放不下的交给用户定。**
例：丝印字宽按平均 0.85 × 字高估，GND、MODULE 这类宽字母多的字实际约 0.9，DRC 还剩 2 条违规。GND 往下挪 0.42 mm 解决；MODULE 在整个模块里都找不到地方，问用户后删掉了（只留 QPA2609）。
做法：
- 规划时留余量（宽字母按 1.0 × 字高）；
- 开着丝印规则跑一次 DRC，用 `scripts/drc_report.py --texts` 只看新加的字；
- 剩下的逐个修；改内容（删字、缩短）属于设计决定，问用户。

**17. 删除这类不可逆操作由用户决定；权限检查拦下时，不改权限、不绕过。**
例：子代理删 MODULE 时被 Claude Code 的权限检查拦下（"不可逆的删除"），主会话转告"用户已同意"也不认。最后是用户自己在 AD 里点删除。用户原话："确实你的禁止删除规则是对的没我允许不许随意放行这个"。
做法：给用户对象的位置、层、文字内容和操作步骤，请他手动删；删完派子代理核对。
