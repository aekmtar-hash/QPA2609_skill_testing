# 三张清单

远程模式三张都用；本机模式 A 节的"压缩包"和 B 节的"截图"可以省（主会话能直接读文件和 DRC 报告），其余照做。

## A　动手前自查（规划端；远程模式每次出包、本机模式每次派修改任务前过一遍）

**数据**
- [ ] 所有数字都由同一个坐标源生成，没有手抄的。改过坐标源后，**所有**输出都重新生成过（指南、数据、清单、图、压缩包）。
- [ ] 自检全过：间距（规则加余量）、连通、每个元件都已摆放、外框不重叠、区域（切口）、板边、孔距、阻焊桥、库禁布区、丝印。
- [ ] 现有设计的模型来自侦察数据；没有侦察数据的，已在说明书里写明"按记录建模"，并留了余量。
- [ ] 现有设计的**所有**铜都在模型里（原有的供电线、地线、过孔），不只是受保护的射频线。（第二轮：原板 VG 线没进模型，一个缝合孔离它 0.025 mm。）
- [ ] 通孔焊盘按真实形状建模（方的 / 圆的 / 八角）。
- [ ] 每个外部封装都跑过 `scripts/pcblib_inventory.py --texts`："层 × 图元类型"统计表里 Top、Keep-Out 层上的 region 已经处理（改库，或者加一步把它挪到机械层），Top Overlay 上自带的文字（`.Designator`、`REFDES`…）已经决定去留。
- [ ] 丝印检查里包含封装自带的 Top Overlay 线、弧和文字；字宽按 0.85 × 字高、宽字母多的按 1.0（第二轮：新字 36 条违规；第三轮按 0.85 还剩 2 条）。
- [ ] 文字全是 ASCII（Value、Comment、网络名、丝印内容）。
- [ ] 差量包：同时对"设计模型"和"实际状态模型"做了检查；"必须保留"清单用的是实际坐标。

**人会看的东西**（都要写成正式阶段，不能写"可选"）
- [ ] 丝印：
  - 字高 / 线宽（默认 1.0 / 0.16 mm）；
  - 哪些位号藏起来、哪些留；
  - 端子旁写电压和极性；
  - 位号要靠近自己的元件、不进别人外框、不压焊盘和过孔、在切口内。
- [ ] 缝合孔：坐标表；和原设计比密度（每平方毫米多少个，或者原来那块区域内的个数）；错行；只对射频线留 1 mm。
- [ ] 预览图（整板 + 局部放大）自己看过一遍：拿原设计截图对比，有没有哪里明显"不像"。

**说明书**
- [ ] 通读一遍查自相矛盾：禁止条款和阶段指令有没有打架（例子：一边"不准动 J3～J6"，一边让改它们的孔径）。写明优先级：禁止条款 > 阶段指令 > 建议。
- [ ] 每个阶段都有可量化的核对门槛（数量、坐标误差、网表一致、DRC 每项违规数）。
- [ ] 每一种删除都写成"允许删除清单"，或者"白名单差集 + 正好 N 个"；删完要数一遍必须存在的对象。
- [ ] 不认识的对象只查不删。
- [ ] 工具做不了的事（实测表里的）已经从代理的清单里拿掉，放进"你自己要做的"。
- [ ] 每一种**没实测过**的工具能力（例如隐藏位号、转文字），都安排在 R0 拿一个对象先试，并写好"做不到时怎么办"；没实测过的调用放在阶段末尾，调用前先保存。
- [ ] 临时规则会被**原有**对象触发多少条，先算出来写进说明书（第二轮 RF_to_Via 被原有屏蔽孔触发 84 条），让执行端分得清哪些是新孔的问题、哪些不用管。
- [ ] 文档名写成"以工程实际引用的为准"，并要求执行端报告改的是哪个文件。
- [ ] `ops.jsonl`：
  - 每种 op 在 RUNBOOK 的工具映射表里都有一行；
  - 每阶段最后一条是 SAVE_AND_LOG；
  - 条数、每阶段条数和指南里写的一致。
- [ ] 人类版指南和代理包用的是同一套坐标；用户要手动做的步骤，没核实过的菜单标【未见过】。
- [ ] 本机模式：任务说明按 `subagent-prompts.md` 的模板写全（路径、只准改什么、备份、带回什么、何时停）；附期望清单 CSV；写明"任何一项不符就停，不保存"。
- [ ] 要直接改 PcbDoc 的：按 `pcbdoc-direct-edit.md` 的顺序；改文字层时两份层号一起改（`pcbdoc_io.patch_texts` 会做），改完 `v7check` = 0。

**压缩包**
- [ ] 一次修改只出**一个** zip，文件名带轮次和日期；旧的、内容不同的同类包删掉或改名，别让用户发错。
- [ ] 解压到空文件夹，把说明书里提到的每个文件名逐个找一遍，都在包里。（第二轮：手册引用的 RUNBOOK_HAIKU.md 不在用户发过去的那个包里。）
- [ ] 文件数和说明书"文件"一节对得上。

## B　跑完验收（人 + 规划端）

**先读执行端的报告和日志**（本机模式：子代理的汇报）：
- 完成到哪个阶段；
- 偏移；
- 每阶段的核对数字；
- DRC 汇总（以 `.drc` 报告为准；本机模式主会话自己用 `scripts/drc_report.py` 读一遍）；
- 本机模式：AD 保存后，主会话用 `pcbdoc_io.py` 重新解析文件，确认改动都在；
- 日志里标了 DEVIATION、MISTAKE、SKIPPED、workaround 的地方，逐条看；
- 执行端给出的**原因和解释**单独列出来，每条找读回数据核对；核对不了的，让人在 AD 里看。

**让用户截图**（远程模式规划端看不到 AD，截图是唯一能看到实物的办法；本机模式也建议让用户在 AD 里看一眼整体）：
1. 整板，所有层都打开（看整体：缝合孔密度、丝印、有没有来历不明的线或框）。
2. 只开 Top Overlay + Top Layer（看丝印压不压焊盘、字大小是否一致）。
3. 只开内层，逐层看（铺铜完整、内层走线）。
4. 3D 视图（元件有没有重叠、方向对不对）。
5. 报告里提到被改动或补回的地方，局部放大看。

**要人在 AD 里亲手做的**：
- 跑一次 Update PCB，看变更列表应该为空（执行端没走正常 ECO 的时候尤其要做）；
- 工具改不了的规则（例如 Minimum Solder Mask Sliver）手动改，再跑 DRC；
- 临时开过又说"已关回"的规则，打开规则看 Enabled 有没有真的取消；
- 中途 AD 崩溃或重启过的：工程面板里有没有多出来的文档，有没有多开的 AD 窗口；
- 出 Gerber。

## C　处理反馈（规划端）

1. 每条问题分四类：**我的数据错 / 执行端错 / 工具限制 / 说明书缺漏**。执行端临场换的办法（workaround）另外列出来：效果一样吗？有没有副作用？（例：文字换成普通文字后和元件不再绑定。）
2. "我的数据错"：先在自检里复现（改模型后，自检能报出同样的问题），复现不了说明模型还不对。
3. 改数据源 → 重新生成全部输出 → 自检 → 出图。
4. 执行端在现场做的改动：写进"实际状态模型"；新数据不一定要照抄它的改法，按规则留足余量重新算。
5. 出**差量包**（基于实际做成的板子，不从头做）：
   - 只包含要改的；
   - 有自己的 R0（确认文档、备份、盘点、校准、试没验证过的工具）；
   - 删除照样用差集 + 计数。
6. 更新：
   - 全量包，留给以后整套重做；
   - 本 skill：经验写进 `references/lessons.md`（`SKILL.md` 里只加标题），工具的坑写进 `references/eda-agent-pitfalls.md`（按主题放，不按轮次），实跑记录写进 `examples/<项目>/README.md`，通用的新脚本收进 `scripts/`。
7. 给用户讲清楚（用大白话）：做成了什么；哪些是我的错、已经怎么改；执行端改了哪里要人去看；哪些要人自己动手。
